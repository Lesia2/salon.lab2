# Юзкейси системи «Салон краси»

## Домен

Система онлайн-запису до майстрів салону краси. Клієнт реєструється, переглядає майстрів та їхній графік роботи і записується на зручний час. Адміністратор керує майстрами, їхніми графіками та записами.

## Актори

| Актор | Опис |
|---|---|
| **Гість** | Неавторизований користувач. Може лише зареєструватися або увійти |
| **Клієнт** | Зареєстрований користувач з роллю `client`. Записується до майстрів, керує власними записами |
| **Адміністратор** | Користувач з роллю `admin`. Керує майстрами, графіками та всіма записами |

## Сутності

| Сутність | Основні поля |
|---|---|
| **Client** | id, ім'я, email, телефон, хеш пароля, роль (`client` / `admin`) |
| **Specialist** | id, ім'я, спеціалізація, активний (так/ні) |
| **Schedule** | id, майстер, день тижня, початок роботи, кінець роботи |
| **Appointment** | id, клієнт, майстер, початок, кінець, статус (`booked` / `cancelled` / `completed`), коментар |

## Інваріанти (бізнес-правила)

| # | Правило | Порушення → HTTP |
|---|---|---|
| I-1 | Email має бути валідним | 400 |
| I-2 | Email унікальний серед клієнтів | 409 |
| I-3 | Пароль — щонайменше 8 символів | 400 |
| I-4 | У графіку початок роботи раніше за кінець | 400 |
| I-5 | Для одного майстра — не більше одного запису графіка на день тижня | 409 |
| I-6 | Початок запису раніше за кінець; запис у межах одного дня | 400 |
| I-7 | Запис не може бути в минулому | 400 |
| I-8 | Запис повністю потрапляє в робочі години майстра за графіком | 400 |
| I-9 | Запис не перетинається з іншими активними (`booked`) записами цього майстра | 409 |
| I-10 | Записатися можна лише до активного майстра | 400 |
| I-11 | Змінити або скасувати можна лише запис у статусі `booked` | 409 |
| I-12 | Клієнт може змінити або скасувати запис не пізніше ніж за 2 години до початку (на адміністратора обмеження не діє) | 409 |
| I-13 | Не можна видалити майстра, у якого є майбутні активні записи | 409 |

## Загальні правила доступу

- Усі ендпоінти, крім реєстрації та входу, вимагають автентифікації. Запит без валідного токена → **401**.
- Клієнт бачить і змінює лише власні записи. Спроба доступу до чужого запису → **404** (щоб не розкривати факт існування запису).
- Операції адміністратора, виконані клієнтом → **403**.

## UC-01. Реєстрація клієнта

- **Актор:** Гість
- **Передумови:** немає
- **Основний сценарій:**
  1. Гість надсилає ім'я, email, телефон і пароль.
  2. Система перевіряє формат даних (I-1, I-3).
  3. Система перевіряє, що email ще не зареєстрований (I-2).
  4. Система зберігає клієнта з роллю `client`, пароль — у вигляді хешу.
  5. Система повертає дані створеного клієнта (без пароля) — **201**.
- **Альтернативні сценарії / помилки:**
  - 2a. Невалідний email, короткий пароль або відсутнє обов'язкове поле → **400**.
  - 3a. Email уже зареєстрований → **409**.

## UC-02. Вхід у систему

- **Актор:** Гість
- **Передумови:** клієнт зареєстрований
- **Основний сценарій:**
  1. Гість надсилає email і пароль.
  2. Система знаходить клієнта за email і перевіряє пароль.
  3. Система видає JWT-токен доступу — **200**.
- **Альтернативні сценарії / помилки:**
  - 1a. Відсутній email або пароль → **400**.
  - 2a. Клієнта не знайдено або пароль невірний → **401** (однакова відповідь, щоб не розкривати, чи існує email).

## UC-03. Перегляд майстрів і їхнього графіка

- **Актор:** Клієнт, Адміністратор
- **Передумови:** користувач автентифікований
- **Основний сценарій:**
  1. Користувач запитує список майстрів (з можливим фільтром за спеціалізацією).
  2. Система повертає список активних майстрів — **200**. Адміністратор бачить також неактивних.
  3. Користувач запитує деталі майстра.
  4. Система повертає дані майстра разом із графіком роботи — **200**.
- **Альтернативні сценарії / помилки:**
  - 3a. Майстра не існує (або він неактивний і запит від клієнта) → **404**.
  - Немає токена → **401**.

## UC-04. Керування майстрами

- **Актор:** Адміністратор
- **Передумови:** адміністратор автентифікований
- **Основний сценарій (створення / зміна):**
  1. Адміністратор надсилає ім'я та спеціалізацію майстра.
  2. Система перевіряє, що поля непорожні.
  3. Система зберігає майстра — **201** (створення) або **200** (зміна).
- **Основний сценарій (деактивація / видалення):**
  1. Адміністратор деактивує майстра (майстер зникає з вибору для нових записів, існуючі записи зберігаються) — **200**,
     або видаляє майстра — **204**.
- **Альтернативні сценарії / помилки:**
  - 2a. Порожнє ім'я або спеціалізація → **400**.
  - Майстра не існує → **404**.
  - Видалення майстра з майбутніми активними записами (I-13) → **409**. Адміністратору пропонується спершу деактивувати майстра.
  - Запит від клієнта → **403**.

## UC-05. Керування графіком майстра

- **Актор:** Адміністратор
- **Передумови:** майстер існує
- **Основний сценарій:**
  1. Адміністратор надсилає для майстра день тижня, час початку і кінця роботи.
  2. Система перевіряє, що початок раніше за кінець (I-4).
  3. Система перевіряє, що на цей день у майстра ще немає графіка (I-5).
  4. Система зберігає запис графіка — **201**.
  5. Адміністратор може змінити (**200**) або видалити (**204**) запис графіка.
- **Альтернативні сценарії / помилки:**
  - 2a. Початок не раніше за кінець або невалідний день тижня → **400**.
  - 3a. На цей день графік уже існує → **409**.
  - Майстра або запису графіка не існує → **404**.
  - Запит від клієнта → **403**.

## UC-06. Створення запису до майстра

- **Актор:** Клієнт
- **Передумови:** клієнт автентифікований; майстер існує, активний і має графік
- **Основний сценарій:**
  1. Клієнт обирає майстра, час початку і кінця, за бажанням додає коментар.
  2. Система перевіряє коректність часу (I-6) і що він не в минулому (I-7).
  3. Система перевіряє, що майстер активний (I-10).
  4. Система перевіряє, що час потрапляє в робочі години майстра за графіком на цей день тижня (I-8).
  5. Система перевіряє, що час не перетинається з іншими активними записами майстра (I-9).
  6. Система зберігає запис зі статусом `booked` — **201**.
- **Альтернативні сценарії / помилки:**
  - 2a. Початок не раніше за кінець, різні дні або час у минулому → **400**.
  - 3a. Майстер неактивний → **400**; майстра не існує → **404**.
  - 4a. Майстер у цей день не працює або час виходить за робочі години → **400**.
  - 5a. Час уже зайнятий → **409**.

## UC-07. Перегляд записів

- **Актор:** Клієнт, Адміністратор
- **Передумови:** користувач автентифікований
- **Основний сценарій:**
  1. Користувач запитує список записів (з можливим фільтром за статусом, майстром або датою).
  2. Система повертає клієнтові лише його записи, адміністраторові — усі — **200**.
  3. Користувач запитує деталі конкретного запису — **200**.
- **Альтернативні сценарії / помилки:**
  - 3a. Запису не існує або він належить іншому клієнту → **404**.

## UC-08. Перенесення запису

- **Актор:** Клієнт (свій запис), Адміністратор (будь-який)
- **Передумови:** запис існує і має статус `booked`
- **Основний сценарій:**
  1. Користувач надсилає новий час початку і кінця та/або новий коментар.
  2. Система перевіряє статус запису (I-11) і, для клієнта, що до початку більше 2 годин (I-12).
  3. Система перевіряє новий час за тими ж правилами, що й при створенні (I-6 – I-9), не враховуючи сам цей запис при перевірці перетину.
  4. Система зберігає зміни — **200**.
- **Альтернативні сценарії / помилки:**
  - 2a. Запис уже скасований або завершений → **409**.
  - 2b. До початку менше 2 годин (клієнт) → **409**.
  - 3a. Новий час невалідний → **400**; зайнятий → **409**.
  - Запису не існує або він чужий → **404**.

## UC-09. Скасування запису

- **Актор:** Клієнт (свій запис), Адміністратор (будь-який)
- **Передумови:** запис існує і має статус `booked`
- **Основний сценарій:**
  1. Користувач скасовує запис.
  2. Система перевіряє статус (I-11) і, для клієнта, що до початку більше 2 годин (I-12).
  3. Система змінює статус на `cancelled` — **200**. Час звільняється для інших клієнтів.
- **Альтернативні сценарії / помилки:**
  - 2a. Запис уже скасований або завершений → **409**.
  - 2b. До початку менше 2 годин (клієнт) → **409**.
  - Запису не існує або він чужий → **404**.

## UC-10. Позначення запису як виконаного

- **Актор:** Адміністратор
- **Передумови:** запис існує, має статус `booked`, час початку вже настав
- **Основний сценарій:**
  1. Адміністратор позначає запис як виконаний.
  2. Система перевіряє статус (I-11) і що час запису вже почався.
  3. Система змінює статус на `completed` — **200**.
- **Альтернативні сценарії / помилки:**
  - 2a. Запис скасований або вже завершений → **409**.
  - 2b. Запис ще не почався → **409**.
  - Запису не існує → **404**.
  - Запит від клієнта → **403**.
